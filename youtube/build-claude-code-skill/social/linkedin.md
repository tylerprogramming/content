# LinkedIn Post — Build a Claude Code Skill from Scratch

I have 20 Claude Code skills running my entire workflow. Every one of them was built the same way.

Most people treat skills like prompts - write something, hope it works, fix it when it doesn't. That's not skill-building. That's guessing.

Here's the actual process:

👉 Every skill starts with a SKILL.md file. Front matter at the top: name, description, allowed-tools. The description field controls when Claude triggers the skill automatically. Most people skip this and wonder why nothing fires.

👉 Below the front matter: step-by-step instructions written like an SOP for a new hire. Not guidelines - actual steps. What to do, in what order, what the output should look like.

👉 Add a Rules section. Every rule in mine came from a bad output I got in testing. You use it, you see what's off, you fix one thing, you run it again.

👉 Add a reference file. Real examples of outputs you liked. "Match this tone. Avoid this phrasing." One line pointing to it. Output quality jumps immediately.

👉 Two files. That's a complete skill. SKILL.md + a reference doc. I built one from scratch in this video - front matter, instructions, live test, iteration, reference file, all of it.
