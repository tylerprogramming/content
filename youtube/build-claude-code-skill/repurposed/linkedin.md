## Post 1: The SOP Framework

Most people treat Claude Code like a chatbot.

They type a question. They get an answer. They type another question.

The people getting real leverage treat it differently. They write SOPs.

A Claude Code skill is nothing more than a markdown file that contains step-by-step instructions. You write what Claude should do first. Then what. What the output should look like. What rules to follow. What to avoid.

It's the same thing you'd write for a new employee - except this one reads the entire document in milliseconds and follows it exactly, every single time.

The skill I built this week is a hook writer. You give it a video topic. It returns 5 YouTube hooks using 5 different techniques - curiosity gap, bold claim, story open, pattern interrupt, pain/problem - each one labeled and explained.

Took about 20 minutes to build. Has already saved me more time than that.

The shift that changed everything for me was stopping asking Claude questions and starting to write Claude instructions. Skills are how you make that permanent.

## Post 2: The Iteration Loop

The first version of every Claude Code skill I've built was wrong.

Not broken. Just not quite right.

The hooks were too formal. The script was too long. The output structure was close but not what I actually wanted.

This is the part nobody talks about when they demonstrate AI automation - the iteration loop.

You build it. You test it. You look at what's off. You change one thing. You run it again.

My YouTube planning skill - the one that plans every video on my channel - has gone through roughly 15 iterations over 6 months. Each version was better than the last. Now it produces a full video package in under 2 minutes and I rarely need to change anything.

The instinct most people have is to assume if the output isn't perfect on the first try, the approach doesn't work. The opposite is true. A skill that's slightly off is one iteration away from being exactly right.

Start simple. Use it once. Fix one thing. Repeat. That's the whole process.

## Post 3: The Reference File Upgrade

There's a version of a Claude Code skill that does the task.

And there's a version that does the task in your voice, using your style, with your specific patterns and preferences baked in.

The difference is a reference file.

When you build a skill, you can include a file called examples.md in the skill folder. In it: 5 examples of outputs you love, 5 examples of what to avoid, notes on tone and style.

You add one line to the skill instructions: read this file before generating anything.

Now Claude isn't producing generic output - it's producing output calibrated to your specific preferences. The hooks sound like you. The scripts match your pacing. The formatting is exactly what you'd actually use.

The people I know getting the most value from Claude Code aren't using it as a general-purpose assistant. They've built a library of calibrated skills - each one trained on their own examples, tuned to their specific workflow.

That library compounds over time. Every skill you build and refine makes the system more useful. It's an asset that grows.
