worker/seed_todos.py:156 and :187 (Warning). A run that deletes rows can be logged as idle, so the delete may never show up in the runs log.

    return {"unchanged": len(tasks), "expired": len(stale)} if stale else {"unchanged": len(tasks)}
    ...
    db.log_run(customer["id"], "seed_todos", "ok", str(res),
               idle="wrote" not in res)

On a quiet morning the tick expires yesterday's three rows and returns {"unchanged": 3, "expired": 3}. There is no "wrote" key, so the run is passed idle=True, and log_run can skip it if another idle run was logged in the last hour. The contract in db.log_run says "anything that acted always write." This commit adds a new way to act (deleting data), and the idle check wasn't updated to count it. That matters most on the one path that deletes rows.
Fix: idle=not (res.get("wrote") or res.get("expired")).

worker/seed_todos.py:131-133 and :150-151 (Warning). Select-then-delete-by-id has a race that can erase a tick.

    stale = db.select("dashboard_todos", customer_id=f"eq.{cid}", source="eq.auto",
                      done_at="is.null", created_at=f"lt.{start_utc}",
                      select="id") or []
    ...
    for row in stale:
        db.delete("dashboard_todos", id=f"eq.{row['id']}")

The delete filters on id alone. Say the owner ticks yesterday's row after the select but before the delete. The delete then removes a done row, which the commit says is kept as history. The window is small, but the fix is simpler than the current code. Use one filtered delete that checks done_at again at delete time and returns the count:

Keep the select only for the dry-run count. This also turns N round trips into one.
