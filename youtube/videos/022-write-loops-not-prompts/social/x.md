## POST 1 - Thread (prompts vs loops)

**Main tweet:**
Most people use Claude one prompt at a time. Type, wait, read, type the next one.

The guy who built Claude Code stopped doing that. He writes loops that prompt for him. Here is the shift:

**Reply 1:**
A prompt is a vending machine. One coin in, one thing out, then it is over.

A loop is an employee. You tell it what good looks like once and it keeps working until the job is actually done.

**Reply 2:**
The version I like has a funny name. The Ralph Wiggum loop.

It runs the same instruction over and over until the work is finished. Claude Code turned that idea into a plugin, /loop.

**Reply 3:**
Three commands cover most of it.

> /loop runs a task on a schedule
> /goal runs until a finish line you wrote is true
> /batch fans one job across agents

If you learn one, learn /loop.

**Reply 4:**
Mine fires at 7am before I am awake. It does the boring research, drafts the work, then stops.

It does not send anything. It waits for me. I approve the good ones with coffee.

**Reply 5:**
A loop is only as safe as its guardrails. Four parts. It knows the intent. It has something that can say no. It has skills worth calling. And it can always stop.

**Reply 6 (CTA):**
You do not need to code for any of this. Pick one boring weekly task, do it by hand once, then wrap it in /loop.

Full walkthrough: https://www.youtube.com/watch?v=RQ57cUcGDGg

## POST 3 - Standalone, the tactic (no link)

Do not start with a loop. Start with one good result.

Make Claude do the boring task by hand once, until you actually like the output. Then wrap that exact thing in /loop. Now it happens without you.

## POST 4 - Standalone, what a loop is (link)

A loop in Claude Code is a task that runs itself on a schedule.

You give /loop an interval and a job. It fires quietly in the background, and it expires on its own so it cannot run forever.
