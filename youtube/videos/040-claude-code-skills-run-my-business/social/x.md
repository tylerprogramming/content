## Thread A - The anti-demo open (RECOMMENDED)

**Main**
Most AI business demos are built for the demo. Tab closes, nothing keeps running.

So I opened the stack that actually runs my content business instead. 17 skills, and not one of them is code.

**Reply 1**
A skill is a folder with one text file in it.

The top says when to use it. The rest is the instructions, in plain English. That is the whole thing.

**Reply 2**
Nothing to install. No code to compile.

You write down what you want done once, and it becomes a command you can run forever.

**Reply 3**
A few of mine run on a schedule while I am asleep.

They all default to draft mode, so nothing goes out without me reading it first.

**Reply 4**
They are not always right either. Call it 80 percent, and I do the last bit.

That is still an afternoon I get back every time.

**Reply 5**
The rule I use now: if I did it twice this month by hand, it should be a text file.

You stop doing the task and start reviewing the result.

## Standalone tweets (post separately, not as a thread)

**1. Hot take**
"Claude Code is for developers" is doing a lot of damage.

A skill is a markdown file with instructions in it. That is the barrier to entry.

**2. Hot take**
The AI money videos all have the same tell.

The business only exists inside the video. Nothing is still running the next morning.

**3. Practical**
The cheapest automation win nobody takes:

Write down the thing you explain to yourself every time. Save it as a text file. Now it runs on command.

**4. Practical**
Default every automation to draft mode.

It finds the work, it writes the first pass, you approve. You get the speed without handing over your judgment.

**5. Practical**
Do not try to build the perfect skill.

Write a rough one, use it, fix the one line that annoyed you. Mine got good by being used, not by being planned.

**6. Reframe**
The point of automating a task is not that the task disappears.

It is that you go from doing it to reviewing it. Different job, way less of your day.
