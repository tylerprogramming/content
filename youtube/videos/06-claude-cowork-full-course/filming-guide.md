# Filming Guide: Claude Cowork - The Complete Course (Full 1-Hour Class)

**Date:** 2026-06-18
**Estimated filming time:** Spread across 1-2 sessions. Do not try to film an hour in one pass.
**Golden rule:** FILM IT MODULE BY MODULE. Each of the 10 modules is its own take with its own screen recording. The editor stitches them together with chapter cards. This is the only sane way to film an hour-long course, and it lets you re-shoot a single module without redoing the whole thing.

---

## Why Module by Module

- An hour in one take guarantees a flub forces a full restart. Separate takes mean a flub costs you one module.
- Each module gets a clean interface, a fresh screen recording, and a focused talking-head energy reset.
- You can film modules out of order based on which folders and connectors are ready that day.
- Chapter cards between modules give the editor natural cut points and give the viewer a sense of progress.
- Modules chop cleanly into shorts later (one feature per short).

---

## Pre-Recording Setup (do this once, before any module)

### Accounts and app
- Paid Claude plan active, Claude desktop app installed and signed in (Mac or Windows).
- Cowork tab confirmed visible. Do a dry run so you are not discovering UI changes on camera.
- A dedicated **Cowork** folder in Documents, pointed at as the working directory.

### Connectors (have these live before filming Module 5 and 8)
- Gmail connector connected.
- Google Drive connector connected.
- Notion (or Google Sheets if you do not use Notion) connected.

### Memory and skills (so demos look real, not first-day)
- A real CLAUDE.md in the Cowork folder with your business instructions (you will show this on camera in Module 3).
- Some existing memory entries so the email-voice demo in Module 3 and Module 5 actually sounds like you.
- At least one saved skill so Module 7 has something to reference.
- At least two scheduled tasks already running with real output files, so Module 8 has genuine "before you wake up" outputs to show.

### Folders to prepare (populate before the matching module)
- **client-files/** - 30+ messy files (contracts, invoices, intake forms, proposals, random PDFs) for Module 2A. Name them messily on purpose.
- **receipts/** - 5-6 phone photos of real business receipts for Module 2B (include two overlapping software subscriptions so Cowork can flag the duplicate).
- **analytics/** - exported analytics or clean dashboard screenshots, at least 2 weeks of data, for Module 4A.
- **transcripts/** - 5 competitor transcripts (use /transcribe beforehand) for Module 4B.
- **scripts/** in Google Drive - 10 past scripts for the Module 5B two-source demo.
- An email thread or two ready to triage for Module 3 and Module 5A.

### Recording setup
- Screen recording at clean resolution, cursor visible, app windowed so callouts fit.
- Teleprompter loaded with the word-for-word intro and each module's CueCard line.
- Talking-head and screen-capture audio levels checked once up front.

## On-Screen Safety (read before every screen recording)

This is a real account with real business data on screen for an hour. Protect it.

- **Never show API keys, tokens, OAuth secrets, or passwords.** If a connector setup screen exposes a token, blur it in edit or re-shoot that beat. When approving OAuth, do not let the consent URL with a code linger on screen.
- **Blur or fake revenue numbers.** Analytics demos are great, but mask exact revenue, subscriber counts you do not want public, and anything in a dashboard you would not put on a billboard. Consider a demo data set for the most sensitive numbers.
- **Redact real email content and personal info.** In Gmail triage demos, use threads you are fine showing, or blur sender names and addresses of real people.
- **Watch the file tree.** Finder and the activity panel can reveal folder names, client names, and file paths. Glance at what is visible before you hit record.
- **Watch notifications.** Turn on Do Not Disturb so Slack, email, and message popups do not surface private content mid-recording.
- **Connectors consent screens:** show that you are approving access, but do not show the granular token grant details. The teaching point is "it asks, you approve, you can revoke," not the OAuth internals.

## The Honest-Limitations Modules (do not skip these caveats)

Two modules require you to verify live behavior on camera and state it accurately. This honesty is a core differentiator versus hype videos. Do not let editing or enthusiasm overwrite it.

### Module 6 - Claude in Chrome
- This feature has rolled out gradually and the exact name and availability can change.
- **On filming day, show what is actually live in YOUR app.** Do not promise the viewer a button that is not in their version yet. Point them to where it appears.
- Demonstrate that it drives your real, logged-in Chrome with the tab highlighted, and that it asks before sensitive actions. Show the permission pause on camera.

### Module 8 - Scheduled Tasks
- **Do not claim it runs entirely in the cloud unless you have verified that in your own app.** Whether a scheduled task runs fully in the background or needs the app open can depend on setup and rollout stage.
- Confirm the current behavior live, on camera, and state it plainly: set one, let it fire, and show the output actually appeared.
- Keep the on-camera line from the script: "test it before you bet your morning on it. Trust it after it earns it, not before."

## Module-by-Module Playbook

Each module: a short talking-head intro, the screen-recorded demo(s), then a recap card. Film the screen recording first, then the talking-head beats, so the demo is fresh when you describe it.

### INTRO (0:00 - 3:00)
- **Talking head:** deliver the first 30 seconds word for word from the teleprompter. High energy.
- **Capture:** side-by-side of Claude Chat (typing a question) vs Cowork (a finished spreadsheet appearing in a folder).
- **Safety:** keep prices off screen. Say "a paid Claude plan."

### MODULE 1: Setup (3:00 - 10:00)
- **Capture:** claude.ai/download page, opening the app, clicking the Cowork tab, creating the Cowork folder, pointing it at the folder, labeling the three UI areas (chat, activity panel, settings).
- **Demo:** the first real task - create about-me.md (Cowork interviews you and writes the first piece of memory).
- **Note:** frame the folder as the "memory folder" that holds info about you and gets reused on every task. Emphasize "desktop app, NOT the website." Recap card.

### MODULE 2: File Management and Document Creation (10:00 - 19:00)
- **Demo 2A:** organize the messy client-files folder into named subfolders, rename with date first, generate client-summary.md. Show the messy before, the clean after, then give one piece of feedback on camera.
- **Demo 2B:** receipts - 5-6 receipt photos into an expense spreadsheet plus expenses-summary.md that flags a duplicate subscription.
- **Safety:** blur any real client names in the file tree. Recap card.

### MODULE 3: The Memory System (19:00 - 28:00)
- **Capture:** the Cowork folder showing CLAUDE.md and the memory file.
- **Demo:** have Cowork interview you and build CLAUDE.md, then tighten it on camera, then prove it follows your rules unprompted.
- **Demo:** the email draft that already sounds like you (this is the wow moment - make sure memory is pre-trained).
- **Safety:** the CLAUDE.md you show should not contain private business numbers you do not want public. Recap card.

### MODULE 4: Research and Analysis (28:00 - 36:00)
- **Demo 4A:** weekly performance report from the analytics folder, with recommendations at the top.
- **Demo 4B:** gap analysis from 5 competitor transcripts into a ranked spreadsheet.
- **Safety:** blur exact revenue/sub numbers in the analytics output. Recap card.

### MODULE 5: Connectors (36:00 - 45:00)
- **Capture:** settings > Connectors > add > approve permissions. Show the consent screen approving, but not token internals.
- **Demo 5A:** Gmail inbox triage from the last 48 hours into a triage report plus one draft reply.
- **Demo 5B:** two sources together - read scripts from Google Drive, cross-reference the local analytics report, save locally.
- **Safety:** redact real email content and addresses. State the boundary: "it asks first, you approve, you can revoke." Recap card.

### MODULE 6: Claude in Chrome (45:00 - 52:00) - HONEST-LIMITATIONS MODULE
- **Capture:** the browser tab with the active-tab highlight, Cowork navigating, the permission pause.
- **Demo:** pull a report off a live logged-in dashboard into the Cowork folder.
- **Safety + honesty:** show what is actually live in your app today. Do not promise a button that may not exist in the viewer's version. Recap card.

### MODULE 7: Skills and Plugins (52:00 - 58:00)
- **Demo:** turn the weekly-report workflow into a saved skill, then run it by name.
- **Capture:** the plugins/extensions area, briefly.
- **Note:** the message is "build skills from work you already do well." Recap card.

### MODULE 8: Scheduled Tasks (58:00 - 68:00) - HONEST-LIMITATIONS MODULE, THE PAYOFF
- **Demo 8A:** the morning brief output that was done before you woke up.
- **Demo 8B:** the Monday report with week-over-week numbers.
- **Build live:** prove it manually first, create a new task, describe it, set the schedule, confirm it has folder/connector/skill access, save, verify the first run.
- **Honesty:** confirm on camera whether it runs in the background or needs the app open. Do not claim cloud execution unless verified.
- **Safety:** blur sensitive numbers in the output files. Recap card.

### MODULE 9: Cowork Plus Claude Code (68:00 - 73:00)
- **Capture:** the Cowork tab and the Code tab side by side, a flow diagram of the real week.
- **Note:** keep it inspirational, "here is what is possible," not braggy. Recap card.

### MODULE 10: Your First Week and Starter Prompt Pack (73:00 - 76:00)
- **Capture:** the clean prompt-pack list on screen (also link in description/Skool).
- **Note:** the on-ramp is small on purpose: one task today, memory plus a connector this week, one scheduled task by the weekend. Recap card.

### OUTRO + CTA (76:00 - 78:00)
- **Talking head:** the one action (hand off one weekly task today), the soft Skool community mention (skool.com/the-ai-agency), the comment prompt.
- **Capture:** community page briefly, end screen card pointing to the Claude Code skills course.
- **Note:** keep it under 2 minutes. One action, one community mention, one comment prompt.

## Recommended Filming Order (efficiency)

1. **Session A - configuration-light modules:** Intro, M1 Setup, M2 Files, M3 Memory, M4 Research, M7 Skills, M9 Cowork+Code, M10, Outro. These only need folders and memory ready.
2. **Session B - connector and live modules:** M5 Connectors, M6 Chrome, M8 Scheduled Tasks. Film these once Gmail/Drive/Notion are live and your scheduled tasks have produced real outputs. These are the modules that need the honest-limitations verification, so give them their own focused session.

Within each module, film the screen recording first, then the talking-head intro and recap so your description matches what just happened on screen.

## Production Notes
- Pace: no silence longer than about half a second. It is a course, but it should feel like a fast tutorial.
- Add a small "Module X of 10" lower third per section so viewers feel progress.
- Zoom into the prompt, then the output. Do not show the whole desktop.
- Re-run /chapters on the final edited cut, since module-by-module filming will shift the real timestamps off the script's planned marks.
- Thumbnail capture: a clean shot of Tyler beside the Cowork interface with good expression, plus a clean Cowork dashboard screenshot for the background. Text options: "FULL COURSE" or "AI EMPLOYEE."
