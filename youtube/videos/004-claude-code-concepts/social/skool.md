## POST 1 - The drop

The first time I opened Claude Code I saw a black screen and a blinking cursor and honestly had no idea what I was doing.

So I get why people install it, type one prompt, get lost in the terminal, and quit. It feels like there is way too much to learn before you can do anything useful.

Here is the good news. You do not need all of it. There are about 23 concepts that take you from total beginner to building real things, and I put every one of them in a single video with a live demo in the terminal. No slides, no theory.

A few that matter most.

The context window is Claude's short term memory, and it fills up while you work. When it does, Claude starts forgetting your instructions and the answers quietly get worse. Understanding that fixed half my problems.

CLAUDE.md is the most important file you will make. You write your rules in it once and Claude reads them first every session. No file means you are making it guess.

Plan Mode lets it think before it builds. It goes read only, explores your code, and proposes an approach without touching anything until you approve.

And /rewind is the safety net. Claude checkpoints before every edit, so if it goes down the wrong path you rewind and you are back.

If you are just starting, do not try to learn all 23 at once. Focus on the first ten and the rest gets easy.

## POST 2 - The tactic (try this today)

Here is a small thing you can do today that changes how Claude behaves for you, and it takes about ten minutes.

Stop re-explaining your preferences in every new chat. Write them down once in a file the AI reads before it starts.

In Claude Code that file is CLAUDE.md. It sits in your project folder and gets read at the start of every session.

Mine is boring on purpose. How I want things named. What I never want in written copy. Which folder things go in. What a good result looks like when it is done right.

None of it is clever. It is just the stuff I got tired of typing over and over.

The easiest way to build one is to not sit down and write it. Instead, the next time you correct Claude, do not only fix it in the chat. Add that correction to the file.

Do that for a week and you end up with a file that makes every future session start smarter than the last one.

The same idea works far outside code. How you want your email drafted, your notes summarized, your reports formatted. If you have explained it twice, it belongs in a file.

You can see how I structure mine, plus every skill I use, free and public here: github.com/tylerprogramming/claude-skills
