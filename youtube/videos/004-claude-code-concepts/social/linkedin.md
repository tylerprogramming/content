## POST 1 - The story

The first time I opened Claude Code I saw a black screen and a blinking cursor.

I typed one thing, got confused, and closed it.

That is how most first sessions go. Install it, type a prompt, get lost in the terminal, decide it isn't for you.

Here is what actually changed it for me.

Claude Code has way more features than you need. I counted 23 concepts worth knowing, and I use maybe six of them on a normal day.

The rest just sit there until the day I need one.

So instead of trying to learn the whole tool, I learned three things first.

The context window. It is Claude's short term memory and it fills up while you work. When it fills, Claude starts forgetting what you told it and the answers quietly get worse. Once I understood that, half my problems went away.

CLAUDE.md. A plain text file in the project folder where I write my rules down once. How I like things done, what to avoid, where things go. Claude reads it first every session, so I am not re-explaining myself in every new chat.

Plan Mode. Before it builds anything it goes read only, explores the code, and tells me the approach. I approve the plan, then it builds. Think first, build second.

That is it. Those three took me from confused to actually finishing things with it.

Everything after that made more sense because I had somewhere to put it. Rewind, skills, MCP servers, sub agents, hooks, running the whole thing from my phone.

So if you are staring at a blinking cursor right now, do not try to learn all 23 at once.

Focus on the first ten. Get comfortable, then add one when you hit the wall that needs it.

## POST 2 - The tactic (no link)

Most people re-explain themselves to AI every single time they open a chat.

Use this format. Do not write it like that. Here is the context you need. The same paragraph, forty times a week.

There is a simpler move, and it works in almost any AI tool now.

Write your rules down once, in a file the AI reads before it starts.

In Claude Code that file is CLAUDE.md. It sits in the project folder and gets read at the start of every session.

Mine is boring. How I want things named. What I never want in written copy. Which folder things belong in. What a good result actually looks like.

None of it is clever. It is just the stuff I got tired of typing.

Here is how to build one without overthinking it. The next time you correct the AI, do not only fix it in the chat. Add the correction to the file.

Do that for a week and you have a file that makes every future session start smarter than the last one.

That is the part I think people miss. This is not a prompt trick. It is a memory you own and can edit.

And it works far outside code. Same idea for how you want your email drafted, your reports formatted, your notes summarized.

The test is simple. If you have explained something to an AI twice, it belongs in a file, not in a chat.

I am not going to tell you it makes the model smarter. It does not. It just stops you from spending the first ten minutes setting the table.

## POST 3 - The honest take (soft link)

I have used Claude Code nearly every day for a year, and I still only use about six of its features.

There are 23 concepts in it. Context, CLAUDE.md, Plan Mode, rewind, skills, MCP servers, sub agents, hooks, and more.

I made a whole video walking through every one of them with a live demo.

And the honest thing to say about it is that trying to learn all 23 is what makes people quit.

The tool is not the hard part. Knowing what you want is the hard part.

Claude will happily build the wrong thing very quickly if you never tell it what good looks like.

It also forgets. The context window fills and it starts dropping instructions you gave it twenty minutes ago. That is not something you prompt your way out of, you just manage it.

Never expect it to be a hundred percent accurate. Eighty or ninety percent, sure, and then you nudge it the rest of the way.

So here is how I would start if I were starting over.

Pick three concepts. The context window, CLAUDE.md, and Plan Mode.

Use those for a week on real work, not a toy project.

Then add one more the first time you hit a wall that needs it.

That is the whole approach. It feels slower than watching a tutorial and it is much faster than trying to hold 23 things in your head.
