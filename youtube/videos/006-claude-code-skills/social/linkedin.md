## POST 1 - The story

I used to explain the same thing to Claude over and over.

Resize these images. Pull a transcript off this video. Ask me my journal questions. The same paragraph, typed out again, every single day.

I did that for months before I bothered to fix it.

What fixed it was skills.

A skill is a saved way of working with Claude. You write down what you want once, and from then on it is one command instead of a paragraph.

I have three I use every day. One pulls a clean transcript from any YouTube video. One asks me a few journal questions and saves a dated file. One helps me script out videos, including this kind of thing.

Each of them took about a minute to build.

Here is the part that surprised me. There is no code involved.

I opened my skills folder to see what one actually looks like. Each skill is a folder, and inside is a single file called SKILL.md. A name at the top, the tools it is allowed to use, then plain English instructions below.

That is the whole skill. A text file.

One detail makes them a lot more useful than they sound. If you put a skill inside a project folder it only works there. If you put it in your home directory it works everywhere, every project, every conversation.

And you update them by asking. When my journal skill was not asking the right questions, I said add one about my mood. It rewrote itself.

So the loop is really simple. Do something with Claude. Like how it came out. Say make a skill out of this.

Then you never explain that thing again.

If you use Claude every day, what is the one task you would turn into a skill first?

## POST 2 - The tactic (no link)

Here is the rule I use now with AI, and it has saved me more time than any prompt I have ever written.

If you have explained the same process twice, stop explaining it and write it down as a file.

Not a longer prompt. A file the AI can load and follow.

In Claude Code these are called skills, and a skill is just a markdown file. A name at the top, the tools it can use, then the steps in plain English below.

The way I write one is not clever at all. I do the task once with Claude, correcting it as I go, until the output is what I wanted.

Then I say make a skill out of this.

It writes down what we just did, including the corrections. Next time it is one command, and I get the same result without re-teaching anything.

The bar here is much lower than people expect. If you can explain your process to someone new on your team, you can write one.

And that is the point I would make even if you never open a terminal. Most of the time we lose to AI is not the thinking, it is the re-explaining. The context you paste in again. The format you correct again. The tone you fix again.

All of that is a file you have not written yet.

Pick one thing you did the exact same way three times this month. Write the steps down like you are onboarding someone. Save it.

That is it. That is the whole tactic.

It takes about ten minutes and it compounds, because every one you write means one thing you never teach again.

What is the task you keep re-explaining?

## POST 3 - The honest take (soft link)

Skills did not make Claude smarter. I want to be upfront about that.

People hear that I run most of my work through saved skills and picture something more impressive than it is.

A skill is a markdown file with instructions in it. That is the entire thing.

What it removed was the typing. The paragraph of context I used to paste in at the start of every task, the same corrections, the same format notes.

What it did not remove is the judgment.

The skill does not know when the output is off. It does not know which draft is the good one. It cannot tell me the idea itself was weak.

That is still me, every time.

And skills go stale. I have written ones I never used again because the task was not actually repeatable, I just thought it was.

The real filter is this. Is the task repeatable and boring? Then hand it off. Is it hard? Hard is usually where the value is, keep that.

Also, never expect it to be a hundred percent right. Eighty or ninety percent, sure, and then you nudge it the rest of the way. That is the honest ceiling.

The mistake I see most is expecting the tool to carry the thinking. It will not, and then people decide the whole thing is hype.

Start smaller than that. One task, one file, this week.

What is the repeatable, boring part of your week you would hand off first?
