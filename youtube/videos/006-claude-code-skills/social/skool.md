## POST 1 - The drop

I kept explaining the same thing to Claude over and over, and skills are what finally fixed it.

Here is the idea. A skill is a saved way of working with Claude. You write down what you want once, and after that it is one command instead of a paragraph you retype every day.

I have three I use every single day. One pulls a clean transcript from any YouTube video. One asks me a few journal questions and saves a dated file. One helps me script out my videos. Each took about a minute to build.

The part that surprised me is that there is no code. Open the folder and a skill is one file called SKILL.md. A name at the top, the tools it is allowed to use, then plain English instructions below. That is the whole thing.

Two more details worth knowing. If you put a skill in a project folder it only works there, and if you put it in your home directory it works everywhere, in every project and every chat. And you can update them just by asking, like telling your journal skill to start asking about your mood.

In the video I show three of mine, open the actual files so you can see what they look like, then build a brand new one from scratch on camera.

It is an older video, but nothing about the idea has changed, so if you missed it, it is worth ten minutes.

## POST 2 - The tactic (try this today)

Here is the rule I use now, and I think it is the single most useful thing I have learned about working with AI.

If you have explained the same process twice, stop explaining it and write it down as a file.

Not a longer prompt. A file the AI loads and follows. In Claude Code those are skills, and a skill is just a markdown file. Name at the top, the tools it can use, then the steps in plain English.

The way I actually write one is not clever. I do the task once with Claude, correcting it as I go, until the output is what I wanted. Then I say make a skill out of this. It writes down what we just did, corrections included. Next time it is one command.

The bar is way lower than people expect. If you can explain your process to someone new on your team, you can write one.

And the idea works even if you never open a terminal. Most of the time we lose to AI is not the thinking, it is the re-explaining. The context you paste in again, the format you fix again, the tone you correct again. That is all a file you have not written yet.

Pick one thing you did the exact same way three times this month and write the steps down. It takes about ten minutes.

All of mine are free and public if you want to copy the format: github.com/tylerprogramming/claude-skills

## POST 3 - The discussion (no link)

I want to ask you all something real, because I have gotten this wrong plenty of times myself.

I run most of my repeat work through saved skills now. Transcripts, journaling, video scripting, a few others. But I have also written skills I never used again, because the task was not actually repeatable, I just thought it was in the moment.

What I have landed on is that the tasks worth automating are the ones that are repeatable AND boring. Not the ones that are hard. Hard is usually where the value is, and you want to keep that part.

The other honest bit is that a skill does not carry the judgment. It does not know when the output is off or which draft is the good one. It only removes the typing.

So here is my question.

What is the thing you do every week, the exact same way every time, that you quietly dread? The one where you already know every step before you start.
