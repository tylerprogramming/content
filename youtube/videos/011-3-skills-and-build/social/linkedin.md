## Post A (RECOMMENDED - teaches the core idea)

Most people use Claude Code like a fancier chatbot. They type a request, get an answer, type the next one.

That's not where the leverage is.

The leverage is in skills. A skill is just a file written in plain English. Sometimes it's 50 lines, sometimes a few hundred, and some of them even generate their own Python scripts. It turns "do this exact thing for me every time" into a single command.

I've built hundreds of them. Many are experiments. But there are 3 I run every single Monday morning, and together they make up a complete content pipeline:

The first pulls every video in my space from the last 30 days, sorts them by views, and writes me a report. Research that used to take two hours now takes sixty seconds.

The second turns any competitor video into a transcript in about 90 seconds, so I can read it instead of watching it. I get through five videos in the time it used to take to watch one.

The third takes that research and drafts a full video package: titles, hooks, a script, a filming guide. A weekend of work compressed into five minutes. It doesn't write the video for me. It writes the 80 percent draft I edit and make mine.

Here is the part that surprises people. At their core, these are just markdown files. No SDK. No framework. Nothing to install. You write what you want in plain English, and Claude Code handles the rest.

So in my new video I build a brand new one from an empty folder, live, in about five minutes.

Once you understand that a skill is just a markdown file, you stop asking "how do I automate this" and start asking "what should I call the skill and what should it say."

What is the first repetitive task you would turn into a command?

## Post B (shorter, hook-led)

Researching YouTube used to take me two hours every week.

Now it takes one command and sixty seconds.

I built a small skill in Claude Code that pulls the last 30 days of videos in my space, sorts them by views, downloads the thumbnails, and writes a report. That report feeds everything else I make that week.

A skill sounds technical. It isn't. It is a markdown file, about 50 lines, written in plain English. Frontmatter at the top that tells the model when to run it, and step by step instructions below.

That is the whole thing.

In my latest video I show three of these running, then I build a brand new one from scratch, live, so you can see exactly how simple it is.

If you have a task you do the same way every single week, that is a skill waiting to be built.

What would yours be?
