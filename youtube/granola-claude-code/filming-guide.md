## MANDATORY: Disclosure (FTC - do all four)

This is a paid partnership and disclosure is required. Do every one of these:

1. **Verbal, in the first 30 seconds.** The disclosure line is written into the cold open in script.md. Say it out loud, clearly, before the first demo runs long. Do not cut it to save time.
2. **On-screen disclosure.** Put a visible "Paid partnership with Granola" or "Sponsored by Granola" lower-third or on-screen card up during the cold-open disclosure beat. Keep it on screen long enough to read.
3. **In the description.** The "Paid partnership with Granola" line is at the very top of description.md. Keep it there.
4. **YouTube paid-promotion checkbox.** On upload, tick YouTube's "This video contains paid promotion" / "Includes paid promotion" box. This adds YouTube's own on-screen disclosure too.

If any one of these is missing, do not publish.

## MANDATORY: Privacy (real meeting data is on screen)

The demos use REAL meeting data with REAL clients and attendees. Protect it.

- **Use safe or demo meetings wherever you can.** The safest path is to record demo meetings or use meetings with people who have agreed to appear. If you must use real client meetings, treat everything as sensitive.
- **Blur on screen:** client names, people's names, email addresses, company names, phone numbers, deal terms, anything financial, and any private or sensitive detail. This applies to Granola notes, Claude Code outputs, the follow-up email drafts, and the proposal.
- **The follow-up email demo (Demo 2) is the highest risk** - recipient names and addresses appear. Blur them. Use a real-but-safe meeting.
- **The proposal demo (Demo 3) names a client and pulls specifics across meetings.** Blur the client name and any identifying scope detail.
- **Rule of thumb:** never show anything a client would not want public. When in doubt, blur it or use a demo meeting instead. Do a full privacy pass in the edit before export.

## Pre-recording setup (do this before you hit record)

- **Granola installed on the Mac with real meeting history.** You need enough past meetings for the cross-meeting demos to be impressive (content patterns in Demo 1, a multi-meeting client history in Demo 3). Sparse history makes the payoff weak.
- **Pick your demo meetings in advance.** Decide which meetings each demo will use, and confirm they are safe to show or can be blurred cleanly. Pre-screen them for sensitive content.
- **Claude Code ready** and open, with a clean terminal/window for the live install. Close anything sensitive in other tabs.
- **Granola MCP install command staged:** `claude mcp add granola --transport http https://mcp.granola.ai/mcp` (copy it somewhere you can paste from).
- **Calendar connected in Granola** so the meeting view and calendar tour beat look populated.
- **Prepare the cold-open payoff.** The opening shot is Claude Code answering "What did I commit to in my meetings this week?" from real history. Make sure that returns something good before you film the open.
- **Run each demo prompt once off-camera** to confirm it returns a strong, safe result. Then film it fresh and real.
- **Disclosure card ready** (on-screen lower-third for the cold open).
- **Notifications off,** menu bar clean, no personal info visible in the OS chrome.

## Per-section capture notes

**COLD OPEN (0:00 - 0:40)**
- Open ON the payoff: Claude Code answering from real meeting history. Not on setup.
- Deliver the disclosure line word for word, fast and honest, with the on-screen disclosure card up.
- B-roll the Claude Code answer scrolling. React naturally. Get straight back to value.
- This is the retention-critical first 40 seconds. No dead air.

**THE PROBLEM (0:40 - 2:00)**
- B-roll: a folder full of meeting notes, scrolling past a wall of old entries nobody reopens.
- Keep it tight. The point is "capture is solved, reasoning across what you captured is the gap."

**WHAT GRANOLA IS (2:00 - 5:00)**
- This is the sponsor's product tour. Keep it MOVING. B-roll over every feature, no slow static talking head, no ad-read energy.
- Capture: a meeting starting with no bot in the participant list, Tyler typing rough notes live, the clean summary appearing after, then the quick tour (calendar, meeting view side by side, Recipes, AI chat).
- Resist letting this turn into a slow ad. Inform, then move to the connection.

**THE MCP CONNECTION (5:00 - 7:00)**
- The credibility core. Film the live install for real.
- Capture: typing/pasting the one command, the OAuth flow opening in the browser, approving, and the Granola tools appearing inside Claude Code.
- "One command, one login, that's the entire setup." Show it actually being true.

**DEMO 1 - CONTENT MINING (7:00 - 9:00)**
- Capture: typing the prompt, Claude Code querying across many meetings (show the work happening), the 5 video ideas grounded in real recurring questions.
- React genuinely to one idea you would not have spotted yourself. That reaction is the proof.
- Blur any client/company name that surfaces.

**DEMO 2 - FOLLOW-UP EMAILS (9:00 - 10:30)**
- Capture: the prompt, Claude Code pulling yesterday's meetings, opening a finished draft.
- HIGHEST privacy risk: blur recipient names and email addresses. Use a real-but-safe meeting.
- The point to land: you did not tell it who was in the meeting or what was discussed - it knew, from the Granola note.

**DEMO 3 - MULTI-MEETING SYNTHESIS (10:30 - 12:00)**
- The "this is the moment it clicked" demo. Give it room to land.
- Capture: the prompt, Claude Code querying multiple meetings across time for one client, the drafted proposal pulling threads from several meetings.
- Blur the client name and identifying scope detail.
- Land the key line: "this is not summarizing one note, it is reasoning across everything."

**WHY THIS WORKS (12:00 - 13:00)**
- Simple two-box diagram: Granola captures, Claude Code reasons. Then show it filling in with more meetings over time (the compounding point).

**CTA (13:00 - 14:00)**
- >> CONFIRM WITH SPONSOR before filming this beat: the exact Granola link, any promo code/offer, free-trial terms, and the precise phrasing Granola wants. The approved script's CTA is a placeholder ("let's talk about it") - do not film final CTA copy until the sponsor confirms.
- Granola CTA is PRIMARY. Talking head, Granola link/offer on screen and in description.
- The Skool community mention is SECONDARY on a paid video - keep it short and after the Granola CTA, do not let it compete.
- End on the comment prompt: "Tell me in the comments what you would ask it first."

## Retention notes

- **Hold the first 30-60 seconds.** Open on the payoff, deliver the fast honest disclosure, get straight back to value. This is where the video is won or lost, especially on a low-search topic.
- **Kill dead air.** Tighten every pause in the edit. No "let me just..." while a command runs - cut to the result or speed it up.
- **B-roll over every demo.** Never a static talking head while something is happening on screen. Show the work: prompts typing, Claude Code querying, outputs appearing.
- **Keep the Granola tour moving.** It is the sponsor section and the easiest place to lose people. Inform fast, b-roll everything, no ad-read cadence.
- **Speed-ramp the slow parts** (install waiting, long generations) so momentum holds.
