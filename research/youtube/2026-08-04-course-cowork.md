# Claude Cowork - Standalone Course Outline

**Type:** Course OUTLINE (structure only, not a script)
**Compiled:** 2026-08-04 (expanded from the ~74 min cut to a full 2+ hour course; then a no-code "build your own Cowork skill" module was added before the capstones, the one thing competitor Cowork courses teach that this outline otherwise routed past)
**Target runtime:** ~144 min (own intro + outro, complete standalone course)
**Audience:** Non-coders, business owners, creators, and students who already use Claude Chat and want the desktop app that does the work instead of describing it. No terminal, no code. Tyler is a software engineer, so the promise is honest: "I build the hard version at a Fortune 500, this is the version anyone can start with today, no code required."
**Voice/rules:** no em dashes, no money amounts in titles, no hype words, drafts before sends, show real runs on camera, admit limits. Honest over impressive. Keep the caveats in (scheduled tasks may run in the cloud vs need the app open, connectors ask first, you stay the one who hits send).

**Format note (say this early):** film it MODULE BY MODULE, each its own screen recording, stitched with chapter cards. Do not attempt one pass. This is now a long course, so chapters in the description are mandatory. Each use-case module is a self-contained mini-lesson with its own inputs, so any one of them can also be cut out as a standalone short or video. If you already have Cowork installed, tell them to jump to Module 3.

**Accuracy note:** Cowork is the desktop app only (claude.ai/download), NOT the browser and NOT the website. It shares one engine with Claude Code but is the no-code surface. Rollout details change (whether a scheduled task runs fully in the background or needs the app open, connector catalog, Chrome availability), so state what is live on filming day and test before relying on it.

**How this expansion works (note to self):** the original was one demo per topic. This version turns each real task into its own mini-lesson with a fresh input pile, a described outcome, a review beat, and a reuse note. The teaching arc is the same the whole way: inputs into the folder, describe the outcome not the steps, review, give ONE correction. Eleven distinct use cases prove that arc from eleven angles so a viewer sees their own job somewhere in the list.

# M2 - Install, setup, and the folder/permission model (0:10 - 0:16) ~6 min

### 2.1 Install it the right way (0:10, 3 min)
Get it right once. Paid plan + the DESKTOP app from claude.ai/download, NOT the website (the number one point of confusion). Open the Cowork tab. Tour the three areas you will live in: the chat, the activity panel (what it is doing, step by step), and settings (where connectors and scheduled tasks live).
- **Task:** install the desktop app, open the Cowork tab, find the three areas.
- **Reuse:** direct from `023/script.md` Module 1 install steps and interface tour.

### 2.2 The folder and permission model, aka the safety habit (0:13, 3 min)
The most important safety idea in the course, said plainly: Cowork can only touch the folder you give it. Create ONE dedicated folder, framed as a memory folder that everything reads from and writes back to. Point Cowork at it. That folder IS the boundary. It does not roam your whole drive, it asks before it reaches outside, and you can revoke access. First task on camera to make the boundary concrete: have it create an about-me.md by interviewing you (the first brick of memory we build on in M13).
- **Task (PROJECT 1):** make the dedicated folder, point Cowork at it, run the about-me interview.
- **Reuse:** direct from `023/script.md` Module 1 (the "memory folder" + "first brick" beats). State the current permission-prompt behavior as it is on filming day.

# M7 - Use case: clean and merge messy data (0:35 - 0:40) ~5 min

### 7.1 Demo: two ugly spreadsheets into one clean joined sheet (0:35, 5 min)
The task that saves an afternoon. Hand it two exports that do not line up: a contacts list and a signups list with different column names, inconsistent casing, duplicate rows, and mismatched date formats. Ask for one clean merged sheet: dedupe, normalize casing and dates, join on email, and flag rows it could not confidently match into a separate tab. The teaching point: Cowork does the boring reconciliation and, crucially, tells you where it was unsure instead of silently guessing. Give one correction (change the match key or the dedupe rule).
- **Task (PROJECT 5):** merge two mismatched spreadsheets into one clean, deduped, normalized sheet with an "unmatched" tab.

The reading you never get to. Drop 4-6 PDFs into the folder (contracts, a couple of reports, a whitepaper, a lease or policy) and ask for one briefing: a two-line summary of each, the three things across all of them that need a decision, and a table of any dates, dollar figures, or obligations. Honest note: for anything legal or financial, it is a first pass to speed you up, not a replacement for reading the part that matters.
- **Task (PROJECT 6):** turn a stack of PDFs into a one-page briefing plus a table of dates/figures/obligations.

# M17 - Scheduled tasks and routines (1:32 - 1:41) ~9 min

### 17.3 Three routines worth stealing (1:37, 2 min)
Give three concrete recurring jobs, each mapped to a use case they already saw: a DAILY morning brief (the M16 calendar + inbox prep, every weekday at 7am), a WEEKLY digest (the M12 report, Monday 8am), and a recurring CLEANUP (the M6 media sort or a "file loose things in my downloads folder" job, every Friday). ### 17.4 The honest part: cloud vs app-open (1:39, 2 min)
Do not skip this. Scheduled tasks / routines can run on Anthropic's servers, which means they can fire even when your laptop is closed. But whether a given task runs fully in the cloud or needs the app open depends on your setup and where the rollout is on filming day, and a routine that needs a local file or a local folder is a case to watch specifically. So test it before you rely on it, and confirm the current behavior on camera. Same rule as always: prove it, then trust it.

# M19 - Common mistakes, permission gotchas, and troubleshooting (1:47 - 1:53) ~6 min

### 19.1 The mistakes that waste your first week (1:47, 3 min)
Run these fast, each with the fix. Installing the website instead of the desktop app (the number one confusion, fix: claude.ai/download). Pointing it at your whole home directory instead of one dedicated folder (fix: the M2 boundary). Describing steps instead of the outcome (fix: the M3 loop, say what you want, not how). Restarting instead of correcting when it is 70 percent there (fix: the M13 one rule). Expecting it to send emails or write to apps without approving (fix: it asks first, by design). Putting a job on a schedule before proving it once by hand (fix: M17's prove-then-schedule discipline).
- **Reuse:** synthesizes the caveats seeded across M2, M3, M13, M14, M17 into one checklist. Net-new module, high value as a standalone short too.

### 19.2 Permission gotchas and troubleshooting (1:50, 3 min)
The specific stumbles and how to read them. A connector that "does not work" is usually an OAuth approval you closed or a scope you did not grant (fix: reconnect, approve the popup, check Settings > Connectors). A custom MCP connector that fails is usually a non-public URL, since it runs from Anthropic's cloud (fix: the M14.5 public-URL rule). A scheduled task that did not fire may have needed the app open or a local file it could not reach in the cloud (fix: the M17.4 caveat, test it). It "cannot find" a file that is outside the folder boundary (fix: move it in, or approve the reach-out). And when a run goes sideways, the activity panel is your log, read what step it stopped on before you re-prompt.

# M21 - Build your own Cowork skill, no code (1:58 - 2:07) ~9 min

### 21.1 What a Cowork skill actually is, in plain English (1:58, 3 min)
The thing competitor courses make sound technical, made simple. A Cowork skill is a saved workflow: you teach Cowork a task you do over and over ONCE, give it a name, and from then on you run the whole job by asking for it by name instead of re-explaining every step. Draw the clean split so nobody confuses it with memory (M13): memory is Cowork knowing WHO you are (your business, your voice, your rules), a skill is Cowork knowing HOW you do one specific job. Plain examples pulled from earlier in the course so it lands as familiar, not new: "run my weekly report" (M12), "triage my inbox the way I like it" (M15), "turn this transcript into my description-and-shorts pack" (M18). No code, no terminal, you describe it in normal words. Honest note: this is the same skills idea that powers Claude Code under the hood, you are just building it by talking instead of writing a file, so state on filming day exactly how Cowork surfaces saved skills or workflows and where they live.
- **Reuse:** callback to M12/M15/M18 outputs so the examples are ones viewers already watched; the "skills = a repeated task you save" framing echoes the Claude Code course. State the current Cowork saved-skill behavior on filming day.

### 21.2 Build one, run it by name, then improve it (2:01, 6 min)
Do it live on a task the viewer genuinely repeats. Use the weekly report from M12 as the cleanest candidate, since they already built it by hand and know what good looks like. The three moves: (1) describe the repeated task to Cowork in plain language, the inputs it starts from, what it should produce, and your format rules, then save it as a named skill; (2) run it by name on this week's inputs and watch it do the whole workflow with no re-explaining; (3) iterate, give it ONE correction (a section order, a tone tweak, an extra column) and save that back into the skill so next time it is already right. The point to say out loud: a skill is just a repeated task you stopped re-describing, and every correction makes the saved version smarter, the exact "correct, do not redo" rule from memory (M13). Then tie it forward and back: the skill you just built is the natural thing to put on a timer (M17), so a good skill plus a schedule is a job that runs itself, and this is why most people never need Claude Code, you can build reusable, no-code skills right here in Cowork (M20).
- **Task (PROJECT 16):** build one small reusable Cowork skill for a task YOU repeat, run it by name, correct it once, and keep it.
- **Reuse:** builds on M12 (the report as the thing you save), M13 (correct-not-redo), M17 (schedule the skill you built), M20 (no-code skills are why Cowork is enough for most people); new footage for the build itself.
