## WEEK 1

### Tue Sep 1, 9:00am - "Claude Code is not a chatbot"

Most people start using Claude Code like it is a better ChatGPT. That is the mistake I made too.

A chatbot answers questions. Claude Code takes actions. It can actually touch your computer. Create files, run commands, install things, build something and then fix it when it breaks.

So the shift that changed everything for me was pretty simple. Stop asking it questions. Start giving it jobs.

Build this. Automate that. Fix this file.

That is module 2 in Claude for Beginners if you want the longer version.

What is one thing you would hand off to it today if you knew it would actually work?

### Wed Sep 2, 9:00am - "The thing that trips up almost everyone"

If Claude ever gives you an answer that feels weirdly off, it is usually not the model. It is that it could not see what you assumed it could see.

Claude only knows what is in front of it. The files you pointed it at, the conversation so far, and whatever tools you have connected. It is not looking at your whole computer. It is not remembering last Tuesday.

Once that clicks, your prompts get better without you trying harder. You stop asking and start showing.

Module 6 covers this properly. I would not skip it. It is kind of the one that makes everything else work.

What is something Claude got wrong for you that turned out to be a context problem?

### Thu Sep 3, 9:00am - "A skill is just a markdown file"

People hear skill and assume there is code involved. There is not.

It is a markdown file. Front matter at the top saying what it is and when Claude should use it, then plain English instructions underneath. That is the whole thing.

You save it, you type the name, and Claude follows those steps every time instead of you re-explaining yourself.

The rule I use: if I have asked Claude to do the same thing three times, it becomes a skill.

Modules 7 and 8 walk through what they are and what they look like in practice.

What is something you have asked Claude for more than three times?

## WEEK 2

### Tue Sep 8, 9:00am - "Build your first skill this week"

If you have been meaning to try this and keep putting it off, this is the one to actually do.

Pick something small. Something you have already asked Claude for a few times. A weekly report, a naming convention, the way you like your notes formatted.

Write it down as steps, in plain English, the way you would explain it to someone sitting next to you. Save it. Type the name.

That is it. It takes about ten minutes, and it is the moment most people tell me it finally clicked.

Module 9 walks you through it start to finish.

What are you going to make yours do?

### Wed Sep 9, 9:00am - "What an MCP actually is"

Everyone keeps saying MCP and almost nobody explains it, so here it is in one line.

An MCP is how Claude talks to something that is not Claude. Your Gmail, your calendar, your database, a scraper, whatever it is.

Without one, Claude can only talk to you. With one, it can go and actually do the thing.

That is the whole idea. Everything else is plumbing.

Module 10 covers it, and it is shorter than you would think.

What is the first tool you would want Claude plugged into?

### Thu Sep 10, 9:00am - "Connecting your first tool"

So once you understand what an MCP is, the next question is always the same. How do I actually connect one?

There are three places you can do it and they are not the same. The desktop app, the web, and inside Claude Code. Each has its own setup and its own reasons you would pick it.

Modules 11 through 13 do all three, one at a time.

Start with whichever one you already use every day. Do not try to do all three at once, you will just get confused and stop.

Which one are you in most, desktop, web, or Claude Code?
