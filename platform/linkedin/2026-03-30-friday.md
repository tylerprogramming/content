# LinkedIn Post - Friday April 3
# Topic: The fastest way to learn Claude Code

The fastest way to learn Claude Code is not to watch tutorials.

I know that sounds backwards coming from someone who makes them.

But every person I've seen get good at this fast did the same thing.

They had a real problem to solve. Claude Code was the tool they used to solve it.

Tutorials show you what's possible.

Building your own thing shows you what's actually hard.

When you have a real project:

You hit real walls and learn how to get past them.

You write prompts that fail and figure out why.

You discover which features actually matter for your use case.

You end up with something useful instead of knowledge you'll forget by Friday.

Here's what I tell everyone who asks where to start:

Pick one thing you already do manually that takes more than 30 minutes. Research, writing, data formatting, scheduling, anything.

Install Claude Code. Try to automate that one thing.

Don't look up how first. Just try.

You'll break things. Claude will misunderstand you. Something unexpected will happen.

Good. That's the lesson.

An hour of struggling on your own problem teaches more than five hours of watching someone else's screen.

Stop preparing to start. Start.

What would you try to automate first if you knew it would work?
