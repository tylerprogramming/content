Here is the rule I use now with AI, and it has saved me more time than any prompt I have ever written.

If you have explained the same process twice, stop explaining it and write it down as a file.

Not a longer prompt. A file the AI can load and follow.

In Claude Code these are called skills, and a skill is just a markdown file. A name at the top, the tools it can use, then the steps in plain English below.

The way I write one is not clever at all. I do the task once with Claude, correcting it as I go, until the output is what I wanted.

Then I say make a skill out of this.

It writes down what we just did, including the corrections. Next time it is one command, and I get the same result without re-teaching anything.

The bar here is much lower than people expect. If you can explain your process to someone new on your team, you can write one.

And that is the point I would make even if you never open a terminal. Most of the time we lose to AI is not the thinking, it is the re-explaining. The context you paste in again. The format you correct again. The tone you fix again.

All of that is a file you have not written yet.

Pick one thing you did the exact same way three times this month. Write the steps down like you are onboarding someone. Save it.

That is it. That is the whole tactic.

It takes about ten minutes and it compounds, because every one you write means one thing you never teach again.
